안전 장치: btn?.addEventListener(...)를 쓰면, 버튼이 없으면 그냥 아무 일도 하지 않고 다음 줄로 넘어갑니다. 앱이 죽지 않는 것이죠.
2026년 실무 가이드
철칙: "내가 찾는 ID가 반드시 이 화면에 있다"라고 100% 확신할 수 있는 경우가 아니라면, 무조건 Optional Chaining(?.)이나 if(btn) 체크를 거치는 것이 Capacitor 공식 문서에서도 권장하는 안정적인 하이브리드 앱 개발 방식입니다.
요약: 로컬 렌더링이라 빠르긴 하지만, 코드가 실행되는 타이밍과 실제 화면에 요소가 그려진 타이밍이 어긋나거나, 파일 간의 요소 공유 문제로 인해 요소가 null인 상황은 언제든 발생할 수 있습니다. 이에 대비해 MDN Optional Chaining 문법을 적극 활용하시길 권장합니다.

1. CSS 아트의 성지 및 참고 사이트
CodePen (코드펜): 가장 추천하는 사이트입니다.
검색창에 CSS Art, Pure CSS, Single Div 등을 검색해 보세요.
도넛, 음식, 캐릭터 등 상상하는 거의 모든 것이 CSS 코드로 이미 구현되어 있습니다.
실시간으로 코드를 수정하며 어떤 속성이 모양을 바꾸는지 바로 확인할 수 있습니다.
CSS-Tricks: CSS Shapes:
복잡한 아트의 기본이 되는 도형(삼각형, 오각형, 하트, 말풍선 등)을 만드는 CSS 공식을 모아둔 곳입니다. 도넛이나 쿠키의 기본 틀을 잡을 때 유용합니다.
A Single Div:
말 그대로 딱 하나의 <div> 태그만 사용해서 얼마나 복잡한 그림(카메라, 게임기, 사탕 등)을 그릴 수 있는지 보여주는 전시관입니다. box-shadow와 background 활용의 극한을 볼 수 있습니다.


Capacitor를 사용한 PWA/SPA 환경, 특히 게임 상점에서 100개의 스킨을 쾌적하게 스크롤하기 위해서는 성능(FPS)과 사용자 경험(UX)을 모두 잡아야 합니다. 2026년 기준 가장 효율적인 방법들을 정리해 드립니다.
1. CSS를 이용한 네이티브 스크롤 (가장 추천)
가장 가볍고 Capacitor 환경에서 "모바일 앱 같은" 느낌을 주는 방식입니다.
구현 방법: 상점 컨테이너에 overflow-y: auto;를 부여하고, 모바일 특유의 탄성 스크롤을 위해 -webkit-overflow-scrolling: touch;를 설정합니다.
장점: 브라우저 엔진의 최적화를 그대로 사용하여 용량이 전혀 들지 않고 매우 부드럽습니다.
팁: 스크롤바가 게임 미관을 해친다면 CSS로 숨길 수 있습니다.
css
.shop-container {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* 3열 배치 */
  gap: 10px;
  height: 80vh; /* 고정 높이 필요 */
  overflow-y: auto;
  scrollbar-width: none; /* Firefox */
}
.shop-container::-webkit-scrollbar { display: none; /* Chrome/Safari */ }

3. 모바일 스크롤 최적화 코드 (필수)
GitHub Pages에서 테스트할 때 아래 CSS 속성을 적용했는지 확인하세요. 이 코드가 있어야 모바일에서 "진짜 앱 같은" 느낌이 납니다.
css
/* 상점 컨테이너 */
.shop-container {
  height: 100vh; /* 화면 전체 높이 */
  overflow-y: auto; /* 세로 스크롤 허용 */
  
  /* 1. iOS용 탄성 스크롤 (없으면 툭툭 끊김) */
  -webkit-overflow-scrolling: touch; 
  
  /* 2. 바운스 효과 방지 (스크롤 끝에서 전체 화면이 들썩이는 현상 방지) */
  overscroll-behavior-y: contain; 
  
  /* 3. 터치 드래그 시 반응성 향상 */
  touch-action: pan-y; 
}

1인 개발자를 위한 CSS 학습 및 구현 전략 요약입니다.
로직화 (Variable-Driven): 스킨을 매번 새로 만드는 대신, 하나의 범용 템플릿을 만들고 CSS 변수(--color, --size)만 JS로 교체하여 100개를 찍어내는 엔지니어링 방식으로 접근하세요.
조립과 재활용: 복잡한 효과(광택, 질감)를 직접 발명하지 말고, CodePen 등에서 검증된 코드 스니펫을 수집하여 내 프로젝트에 맞게 수치만 조정(Tuning)하세요.
도구 활용: 직접 코딩하기보다 CSS Generator(그라데이션, 그림자 생성기)를 사용하여 결과물을 빠르게 '생성'하고, Tailwind CSS 같은 프레임워크로 디자인 수치를 표준화하세요.
관점의 전환: CSS를 '그림 그리기'가 아닌 '스타일 규칙 설계'로 정의하면, 초기 학습 이후 이미지 에셋 제작보다 훨씬 높은 생산성과 최적화 효율을 얻을 수 있습니다.


3. "체력(HP)과 골드" 이원화 방식
점수를 '돈'이 아닌 '생존 수치'로 치환하는 방식입니다.
방식: 초기 점수 500점을 '정신력(HP)'으로 부릅니다. 12라운드 동안 HP가 0이 되면 게임 오버(파산)입니다. 스킨은 게임 종료 시 남은 HP의 양에 비례해서 주는 보너스 재화로 구매합니다.
재미 요소: KK나 NN으로 HP가 깎이면 유저는 실제로 "죽어가고 있다"는 공포를 느낍니다. 살아남기 위해 비굴하게 협력하거나, 죽기 전에 상대를 길동무로 삼으려고 K를 누르는 처절한 서사가 만들어집니다.
장점: '점수'라는 딱딱한 용어보다 게임의 테마(죄수의 딜레마)를 훨씬 더 잘 살릴 수 있습니다.
논의된 '체력(HP) 시스템 기반의 고회전율 심리 게임'에 대한 주요 내용을 요약 정리해 드립니다.
1. 시스템 핵심: '체력(HP)' 방식의 도입
개념: 초기 점수(500점)를 단순한 재화가 아닌 플레이어의 '생존 HP'로 정의합니다.
심리적 효과: 점수가 깎일 때마다 유저는 '파산'이 아닌 '죽음'의 공포를 느끼며, 이는 협력과 배신 사이의 갈등을 극대화하는 장치가 됩니다.
보상 연동: 게임 종료 시 남은 HP의 양에 비례하여 스킨 구매 포인트를 지급함으로써, 생존 자체가 곧 수익이 되는 구조를 만듭니다.
2. 게임 구조: 가혹한 환경과 높은 회전율
짧고 강렬한 호흡: 유저들이 짧은 시간 안에 자주 죽고 다시 시작하게 설계합니다.
광고 수익 최적화: 게임 오버(사망)가 잦을수록 재시작을 위한 광고 노출 기회가 많아져 1인 개발자에게 유리한 수익 모델(BM)이 형성됩니다.
학습과 도전: 유저는 죽음을 통해 상대의 성향을 배우고, "이번엔 더 오래 버티겠다"는 단기 목표를 가지고 즉시 재접속하게 됩니다.
3. 매치메이킹과 심리전: '좁은 사회'의 메커니즘
악연의 재회: 유저 풀이 적어 'K(Kick)'를 해도 다음 판에 다시 만날 확률이 높다는 점을 역이용합니다.
평판의 형성: 지난 판의 배신자를 다시 만났을 때 발생하는 '복수심'과 '어색한 재회'가 게임의 핵심 재미 요소가 됩니다.
전략의 심화: 단순한 숫자 계산을 넘어, 상대방에게 내 평판을 어떻게 관리할지 고민하게 만드는 '사회적 심리전'으로 확장됩니다.
4. 운영 및 보완 전략
패자 부활: HP가 0이 되었을 때 광고 시청 시 소량의 HP로 즉시 부활시켜 매칭 이탈을 방지합니다.
데이터 보존: 죽더라도 '활동 점수' 등 누적 재화를 일부 지급하여 유저가 완전한 허무함을 느끼지 않도록 안배합니다.
시각적 자극: HP가 깎일 때 화면 흔들림이나 붉은 섬광 효과를 주어 생존에 대한 압박감을 시각화합니다.
결론적으로, 이 설계는 "이미지 에셋 없는 CSS 스킨"의 가벼움과 "가혹한 생존 게임"의 묵직함이 결합된 형태입니다. 유저는 도넛 스킨을 얻기 위해 매 판 처절하게 생존 투쟁을 벌이게 되며, 개발자는 높은 회전율을 통해 안정적인 광고 수익과 활발한 매칭 생태계를 유지할 수 있습니다. 행동경제학의 손실 회피와 게임 이론의 반복 게임이 절묘하게 조화된 기획입니다.
